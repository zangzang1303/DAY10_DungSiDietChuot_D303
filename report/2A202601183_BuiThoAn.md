## 4. Giải thích phần kỹ thuật đã thực hiện

### Vấn đề cần giải quyết

Đảm bảo nguồn dữ liệu thô từ Crossref API được thu thập ổn định, làm sạch các chuỗi HTML/XML abstract, loại bỏ khoảng trắng dư thừa, parse ngày tháng xuất bản chuẩn hóa ISO để tính `age_days`, tổng hợp trường `text_for_embedding` chất lượng cao cho ChromaDB vector index, đồng thời đóng đóng băng (freeze) bộ câu hỏi đánh giá 8 mẫu.

### Cách triển khai

1. **Ingestion:** Dùng `urllib.request` gọi API Crossref với query `agentic retrieval augmented generation large language model` và filter `has-abstract:true`. Thêm retry/backoff khi API bận hoặc bị giới hạn rate limit.
2. **Cleaning:** Trích xuất DOI làm `paper_id`. Làm sạch HTML tag trong abstract bằng regex. Parse `published-print` hoặc `published-online` ra định dạng ISO. Tính `age_days = (run_date - published).days`. Tạo `text_for_embedding = f"Title: {title} | Abstract: {summary} | Authors: {authors} | Categories: {categories}"`.
3. **Testset Generation:** Trích xuất 8 câu hỏi đa dạng loại hình (title, summary, author, category) từ các paper đại diện và freeze ra `data/eval/test_set.json`.

## 5. Một quyết định kỹ thuật quan trọng

- **Bối cảnh:** Lựa chọn khóa chính `paper_id` để liên kết giữa Clean Dataset, ChromaDB vector store và Evaluation Test Set.
- **Các phương án đã cân nhắc:**
  1. Sử dụng số thứ tự tự tăng (`0, 1, 2...`).
  2. Sử dụng DOI chuẩn hóa làm `paper_id`.
- **Phương án đã chọn:** Phương án 2 (Dùng DOI chuẩn hóa).
- **Lý do:** DOI là định danh duy nhất và bất biến của bài báo khoa học. Khi thực hiện corruption (ví dụ xóa row hoặc nhân bản), DOI vẫn giữ được tính nhất quán giúp module evaluation tìm chính xác ground truth paper ID.
- **Bằng chứng quyết định phù hợp:** `retrieval_hit_rate` duy trì 1.0 trong cả 3 trạng thái baseline, corrupted và repaired.

## 6. Một lỗi hoặc blocker đã xử lý

- **Triệu chứng/lỗi nguyên văn:** Abstract nhận từ Crossref chứa nhiều thẻ HTML như `<jats:p>`, `<b>`, `<jats:sec>`.
- **Lệnh hoặc bước tái hiện:** `python script/run_phase1.py` khi chưa có regex strip HTML tags.
- **Nguyên nhân gốc:** Crossref API trả về abstract dưới dạng JATS XML/HTML snippet.
- **Cách xử lý:** Thêm hàm clean regex `re.sub(r'<[^>]+>', '', text)` trong `cleaning.py` để xóa triệt me các HTML tags trước khi tạo `text_for_embedding`.
- **Cách xác minh sau khi sửa:** Cột `summary` trong `data/clean/papers_clean.csv` hoàn toàn là văn bản thuần không chứa tag.
- **Điều học được:** Luôn làm sạch định dạng markup ngôn ngữ trước khi tạo vector embedding để tránh làm loãng ngữ cảnh vector.

## 7. Hiểu biết về luồng end-to-end

1. Dữ liệu từ Crossref REST API được fetch dưới dạng raw JSON, sau đó cleaning module lọc trùng, làm sạch văn bản, tính toán `age_days` và tạo `text_for_embedding`. Dữ liệu sạch này được nạp vào MiniLM embedding model để sinh vector embeddings và lưu trữ tại ChromaDB.
2. Evaluation set cố định 8 câu hỏi với `ground_truth_doc_ids` (chứa `paper_id` thực tế). Khi chạy evaluation, hệ thống truy vấn ChromaDB với `top_k=4`, so sánh xem `ground_truth_doc_ids` có nằm trong top-k hay không để tính `retrieval_hit_rate`, và so sánh câu trả lời của LLM với ground truth answer để tính `mean_token_f1`.
3. Quality checks kiểm tra các ràng buộc tĩnh như schema, missing values, duplicates (Completeness, Validity, Uniqueness). Freshness monitoring kiểm tra tuổi đời dữ liệu dựa trên `age_days` so với ngưỡng 180 ngày.
4. Test set phải giữ nguyên 100% qua 3 trạng thái để đảm bảo biến độc lập duy nhất là chất lượng dữ liệu (Data Quality).
5. Repair thành công được xác minh khi quality checks chuyển từ FAIL về PASS và metrics (`mean_token_f1`) phục hồi về mốc baseline.
